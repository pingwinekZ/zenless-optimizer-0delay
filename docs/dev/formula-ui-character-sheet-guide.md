# Formula-UI Character Sheet Guide (Template)

A distilled template for writing `app/src/formula-ui/char/sheets/{Name}.tsx` files, extracted from 19 reference sheets:

Cissia, Dialyn, Yixuan, Lucia, Alice, Yuzuha, Yidhari, Banyue, Zhao, YeShunguang, Aria, Sunna, Promeia, NangongYu, StarlightBilly, Pyrois, Velina, Norma, Remielle.

This file is **UI-only**. It defines *what the user sees and toggles*, not the damage math — the math lives in `app/src/formula/data/char/sheets/{Name}.ts` (see `character-wengine-implementation-guide.md` for that half). If a buff/conditional/formula is referenced here but missing in the data sheet, the UI silently fails to render that row, so always pair the two.

---

## 1. The skeleton (copy-paste template)

Every sheet follows the same shape. Fill in the blanks, delete what doesn't apply:

```tsx
import { ColorText, ImgIcon } from '@zenless-optimizer/common/ui'
import { commonDefIcon, mindscapeDefIcon } from '../../../assets'
import type { CharacterKey } from '../../../consts'
import { Name } from '../../../formula'
import { GameDesc } from '../../../i18n'
import { mappedStats } from '../../../stats'
import { st, trans } from '../../util'
import {
  CoreGameDesc,
  createBaseSheet,
  fieldForBuff,
  SkillGameDesc,
} from '../sheetUtil'
import { getVariant } from '../util'

const key: CharacterKey = 'Name'
const [, ch] = trans('char', key)
const cond = Name.conditionals
const buff = Name.buffs
const formula = Name.formulas
const dm = mappedStats.char[key]

const sheet = createBaseSheet(key, {
  perSkillAbility: {
    basic: {
      BasicAttackName: [
        // conditional or fields documents tied to this skill ability
      ],
    },
    special: {
      EXSpecialAttackName: [],
    },
    chain: {
      UltimateName: [],
    },
  },
  core: [
    // core passive documents
  ],
  ability: [
    // additional ability documents
  ],
  m1: [
    // mindscape documents (m1..m6)
  ],
  m2: [],
  m4: [],
  m6: [],
})

export default sheet
```

### What's optional (delete when unused)

| Const | Needed when | Seen in |
|---|---|---|
| `ImgIcon` | using `commonDefIcon` / `mindscapeDefIcon` headers | Yuzuha, Zhao, Promeia, StarlightBilly, Velina, Norma, Remielle |
| `commonDefIcon`, `mindscapeDefIcon` | a header has an icon | same as above |
| `GameDesc` | any conditional/field needs a locale description | most sheets |
| `mappedStats` / `dm` | a `fieldValue` reads a raw datamine value | Yuzuha, Zhao, Promeia, Remielle |
| `st` | a translated stat label (e.g. `st('heal')`) | Lucia |
| `CoreGameDesc` | a conditional's description cites a core paragraph | Cissia, Lucia, Yuzuha, Yidhari, Banyue, Zhao, Sunna, StarlightBilly, Pyrois, NangongYu |
| `SkillGameDesc` | a conditional's description cites a skill ability | Cissia, Lucia, Yidhari, Zhao, Aria, Sunna, Yixuan, NangongYu, Remielle |
| `formula` const | displaying a formula (custom dmg / heal) rather than a buff | Cissia, Dialyn, Yixuan, Lucia, Alice, Yuzuha, Yidhari, Banyue, Remielle, YeShunguang, Promeia |
| `cond` const | any conditional | all except YeShunguang (she has none) |

> Note: `formula` (from `Name.formulas`) is **only** for custom damage/heal formulas (M6 bonus attacks, heals). Regular skill DMG rows are auto-generated by `createBaseSheet` — never add them manually.

## 2. Document types

Each section (`core`, `ability`, `m1`…`m6`, per-skill) is an array of **documents**. Three types:

```tsx
// 1. Static field group — no toggle
{
  type: 'fields',
  header: { icon: null, text: ch('core_header') }, // header optional
  paragraph: 3,                                    // optional: which core/skill paragraph to pull hover desc from
  descKey: 'special.EXSpecialAttackName.desc',     // optional: full override of the hover desc locale key (Lucia)
  fields: [
    fieldForBuff(buff.core_hpSheerForce),
  ],
}

// 2. Toggleable conditional — renders a switch bound to a metadata conditional
{
  type: 'conditional',
  conditional: {
    label: ch('etherVeilCond'),
    description: <CoreGameDesc characterKey={key} paragraph={3} />,
    metadata: cond.etherVeil,
    fields: [fieldForBuff(buff.core_common_dmg_)],
    linked: 'm1EtherVeil',            // optional — toggling this also toggles the linked conditional(s)
  },
}

// 3. text — always auto-generated by createBaseSheet (skill/core/ability/mindscape
//    descriptions). You almost never write one yourself.
```

**Order within a section matters.** Documents render top-to-bottom and paragraphs are indexed from the text document. Note: `paragraph` and `descKey` are **only** valid on `type: 'fields'` documents — `conditional` documents can't carry them (they're not in the `ConditionalDocument` type).

## 3. The three field patterns

This is the most important recurring decision. Pick based on *what the value is*:

### Pattern A — `fieldForBuff(buff.xxx)` (auto title, most common)

```tsx
fieldForBuff(buff.core_common_dmg_)
```

- Auto-generates the title from the buff's tag (e.g. "ATK", "Anomaly Proficiency", "Crit DMG").
- Auto-attaches `team: buff.xxx.team` when the buff is a team buff (per `sheetUtil.tsx`: `...(buff.team !== undefined ? { team: buff.team } : {})`).
- Use for **any** row whose title can come from the tag. ~70% of rows across the 19 sheets.

> For a **manual** Pattern B row that also needs the team flag, set it explicitly: `team: buff.ability_anomaly_buff_.team` (Yuzuha's `ability_anomaly_buff_` / `ability_disorder_buff_` rows do exactly this).

### Pattern B — manual title + `ColorText` + `getVariant` (custom label, colored by attribute)

```tsx
{
  title: (
    <ColorText color={getVariant(buff.m6_crit_.tag)}>
      {ch('m6_crit_')}
    </ColorText>
  ),
  fieldRef: buff.m6_crit_.tag,
}
```

- Use when the localized label is more specific than the raw stat name (named attacks like "Serpent's Kiss DMG", "Toppling Mountain Sheer DMG").
- `getVariant(tag)` returns the tag's attribute, so the title is colored like the character's attribute in-game.
- Applies to both `buff.*.tag` and `formula.*.tag` (formula rows always use this pattern).

### Pattern C — static datamine value (no tag, no toggle)

```tsx
{
  title: ch('m1_buffInc_'),
  fieldValue: dm.m1.buffInc_ * 100,  // decimals → percent
  unit: '%',
}
```

- For raw values from `mappedStats` that aren't tied to a tag (flat mindscape modifiers, charge rates, trigger counts).
- `fieldValue` + `unit` (e.g. `'%'`, `'×'`) — Remielle's `m6_luminizeTriggerCount` uses `unit: '×'`.
- Percent values from dm come as decimals → multiply by 100.

> **Rule of thumb:** tag exists and title is fine → A. Tag exists but needs a custom/colored title → B. No tag → C.

## 4. Conditional anatomy

```tsx
{
  type: 'conditional',
  conditional: {
    label: ch('m1Cond'),                              // required — toggle label
    description: <GameDesc ns="char_Name_gen" key18="mindscapes.1.desc" />, // optional
    metadata: cond.m1DefReductionStacks,              // required — the conditional object
    fields: [fieldForBuff(buff.m1_defRed_)],          // optional
    linked: ['a', 'b'],                               // optional — string | string[]
    badge: (_, value) => value > 0 ? ch(`teammateSlot_.${value}`) : undefined, // optional (Dialyn)
  },
}
```

### `linked` — the cross-conditional coupling pattern

When two conditionals describe the same buffing state (e.g. a core state and its M1/M2/M6 upgrade), they are **linked** so toggling either flips both. Chains observed:

| Sheet | Linked group | Direction |
|---|---|---|
| Cissia | `venomDefIgn` ↔ `venomCritDmg` | core ↔ ability |
| Lucia | `dreamersNurseryRhyme` ↔ `m1DreamersNurseryRhyme`; `etherVeil` ↔ `m2EtherVeil`/`m6EtherVeil` | core ↔ mindscape |
| Yixuan | `meditation` ↔ `m6_meditation` | ability ↔ m6 |
| Yidhari | `etherVeil` ↔ `m4EtherVeil` | chain ↔ m4 |
| Banyue | `coreExSpecialFollowUpUsed` ↔ `m2ExSpecialFollowUpUsed`; `abilityVidyaraja` ↔ `m6Vidyaraja` | core ↔ m2, ability ↔ m6 |
| Aria | `m2Delusion` ↔ `m6Delusion` | m2 ↔ m6 |
| Dialyn | `overwhelmingly_positive_common` ↔ `resIgn`/`atk` | ability ↔ m1/m4 |
| Remielle | `phaseFlow` ↔ `phaseFlow_daze`/`phaseFlow_m1` | special ↔ ability/m1 |

**Pattern:** name them consistently (`xxx` ↔ `mNxxx`), pass the *other* name(s) as `linked`, and mirror the linkage on both sides so the toggle stays in sync either way.

### `badge`

Rare. Dialyn uses it to render a slot letter ("teammateSlot_.X") next to the toggle based on the current value:

```tsx
badge: (_, value) => (value > 0 ? ch(`teammateSlot_.${value}`) : undefined),
```

## 5. Description components — four ways

### A. `<GameDesc>` — plain locale paragraph(s)

```tsx
<GameDesc ns="char_Name_gen" key18="ability.desc" />            // single
<GameDesc ns="char_Name_gen" key18="mindscapes.2.desc" />       // mindscape
```

### B. Multi-paragraph fragment

```tsx
description: (
  <>
    <GameDesc ns="char_Name_gen" key18="ability.desc.0" />
    <div style={{ marginBottom: 8 }} />
    <GameDesc ns="char_Name_gen" key18="ability.desc.3" />
  </>
),
```

Used when a single desc has several paragraphs and only specific ones apply (Dialyn, Yuzuha, Yidhari, Banyue, StarlightBilly, Norma, Cissia).

### C. `<CoreGameDesc>` — core passive desc at the character's *actual* core level

```tsx
<CoreGameDesc characterKey={key} paragraph={3} />
```

- Resolves `core.desc.{coreLevel}.{paragraph}` using the character's real core level.
- Omit `paragraph` to render all paragraphs for the level.
- Also needed inside `perSkillAbility` descriptions? No — that's `SkillGameDesc`.

### D. `<SkillGameDesc>` — skill ability desc with `{CAL:...}` tokens evaluated

```tsx
<SkillGameDesc
  characterKey={key}
  ns="char_Name_gen"
  key18="special.EXSpecialAttackName.desc"
/>
```

- Evaluates `{CAL:...}` math tokens in the locale text using the character's actual skill levels (including M3/M5 +2).
- **key18 must match a real dm ability key**, e.g. `chain.UltimateOphidiophobia.desc`, `basic.BasicAttackFinalVerdict.desc`.

## 6. `perSkillAbility` — tying conditionals to a specific skill

Keys under `basic` / `special` / `chain` / `dodge` / `assist` must be the **exact dm ability key** (from `char_{Name}_gen` locale / dm data):

| Sheet | skill | ability key used |
|---|---|---|
| Cissia | chain | `UltimateOphidiophobia` |
| Cissia | basic | `CorrodeBone` |
| Lucia | special | `EXSpecialAttackSymphonyOfTheReaperDaybreak` |
| Yidhari | chain | `EtherVeilWellspring` |
| Zhao | basic | `BasicAttackFinalVerdict` |
| Aria | chain | `Ultimate100Energy` |
| Sunna | special | `EXSpecialAttackSpecialPhotographyTechnique` |
| NangongYu | chain | `UltimateMeteorShower` |
| Remielle | special | `SpecialAttackOdeToDawnRadiantTurn` |

Notes:
- Each ability value is a `Document[]` appended *after* the auto-generated DMG/daze/anom rows for that ability.
- A skill with **no** additional docs can be omitted entirely — but an *empty* object (`special: {}`, Zhao) is harmless and explicit.
- **Ability + M1 upgrade of a skill state**: put the base conditional under the skill and the mindscape conditional in `mN`, then `linked` them (Yidhari `etherVeil` ↔ `m4EtherVeil`).
- **`fields` with `descKey`** (Lucia): `descKey: 'special.EXSpecialAttackSymphonyOfTheReaperDaybreak.desc'` overrides the hover-card desc key for that row — used when a fields doc sits under a skill whose desc key isn't inferred correctly.

## 7. Headers & icons

```tsx
// Plain text header (most common)
header: { icon: null, text: ch('core_header') }

// Core passive header with icon
header: {
  icon: <ImgIcon src={commonDefIcon('coreFlat')} size={1.5} />,
  text: ch('core_header'),
}

// Mindscape header with icon
header: {
  icon: <ImgIcon src={mindscapeDefIcon(1)} size={1.5} />,  // or 4, 6
  text: ch('m1_header'),
}
```

- `commonDefIcon('coreFlat')` for core/ability section headers; `mindscapeDefIcon(N)` for mindscape N.
- `size={1.5}` is the standard icon size.
- Headers are optional on `fields` docs (Lucia's `chain` fields doc has none; NangongYu's m6 has none). When omitted, the section still renders — the header just isn't shown.

## 8. Paragraph / index overrides

`createBaseSheet` auto-generates the core text (paragraph by core level), ability text, and per-skill texts. The `paragraph` keys let you override which paragraph an added row's hover description resolves to:

| Prop | Where | Meaning |
|---|---|---|
| `coreParagraph` | top-level sheet | pick which core desc paragraph the core text doc shows |
| `abilityParagraph` | top-level sheet | pick which ability desc paragraph the ability text doc shows (Alice uses `abilityParagraph: 2`) |
| `paragraph: N` | on a `fields` doc only | override the auto-computed paragraph index used for that row's hover desc (Yixuan `core` uses `paragraph: 5`; Lucia's special fields doc uses `paragraph: 3`; Remielle's core fields use `paragraph: 3`). **Not valid on `conditional` docs** — the `ConditionalDocument` type has no `paragraph`/`descKey`. |
| `descKey` | on a `fields` doc only | full override of the hover desc locale key |

> **Remielle's comment (the canonical example):** "paragraph=1 on the Daze field overrides the auto-generated index 2 (Prismatic paragraph) to show the ATK/Daze paragraph instead."

## 9. Section-level conventions

| Section | Convention |
|---|---|
| `core` | Always present, even if `[]` (Alice). Static core stats go in `fields`; state-gated core buffs go in `conditional`. |
| `ability` | Can be `[]` when ability has nothing extra (NangongYu) or when `abilityParagraph` handles everything (Alice). |
| `m1`/`m2`/`m4`/`m6` | Only mindscapes with *displayable* buffs need sections. Missing sections (e.g. no `m3`/`m5` anywhere) are fine — those are auto +2 skill levels with nothing to display. |
| Multiple docs per mindscape | Split different effects into separate documents (Velina's m1: two conditionals + one fields doc). |

### Locale key naming conventions (`ch('...')`)

- Conditional labels: `xxxCond` (e.g. `etherVeilCond`, `m1Cond`, `abilityCond`)
- Section headers: `core_header`, `ability_header`, `m1_header`, `m2_header`, …
- Buff/formula titles: usually mirror the buff name (`m6_crit_`, `core_common_dmg_`, `m6_dmg`)
- `ability_dmg`, `m1_dmg`, `m6_dmg` → custom formula titles
- Special cases: `m6AdditionalDmg`, `luminizeRainbowsEndDmgInst`, `teammateSlot_.{n}`

## 10. Checklist — applying this to a new character

- [ ] Read the data sheet (`app/src/formula/data/char/sheets/{Name}.ts`) and list every `registerBuff` + conditional + formula.
- [ ] Copy the skeleton; prune imports to what's actually used.
- [ ] Add `perSkillAbility` docs for skill-embedded states; verify ability keys against the dm locale (`char_{Name}_gen`).
- [ ] Add `core` docs: static stats as `fields`, state-gated as `conditional` with `CoreGameDesc` descriptions.
- [ ] Add `ability` docs; use `abilityParagraph` when the ability desc has multiple paragraphs.
- [ ] For each mindscape: `fields` for unconditional buffs, `conditional` for gated ones.
- [ ] Wire `linked` between a state and its upgrades (name pairs `xxx` ↔ `mNxxx`).
- [ ] Prefer `fieldForBuff`; use Pattern B only for custom/colored titles; Pattern C for raw dm values (×100 for %).
- [ ] Add any missing locale keys to `app/src/localization/assets/locales/en/char_{Name}.json`.
- [ ] Register the sheet in `app/src/formula-ui/char/sheets/index.ts` (it's a generated file — regenerate or add manually if the generator doesn't cover it).
- [ ] `bun run mini-ci` to verify typecheck/lint/tests.

## 12. Gotchas

1. **`formula` rows must use Pattern B** (manual `ColorText` title) — never `fieldForBuff`, since formulas don't have display-friendly tag titles.
2. **Empty `core: []` / `ability: []` is valid** — don't invent rows to fill space.
3. **Never manually add skill DMG/daze/anom rows** — `createBaseSheet` generates them; your docs *append* to them.
4. **`linked` must be mirrored** — if A lists B, B should list A (or the group), or toggles desync.
5. **Paragraph indexes are 0-based** in locale keys (`ability.desc.0`), matching `core.desc.{level}.{paragraph}` structure.
6. **dm decimals** — `dm.m2.buffInc_ * 100` with `unit: '%'`; don't pass raw decimals to a `%` unit.
7. **`getVariant` only returns a color when the tag has an `attribute`** — it's a color, not a style helper.
8. **Sheet registration** — `sheets/index.ts` is generated; if your generator doesn't run for a new character, add the import + map entry manually.
